# Benchmark: mri-metadata-prepare

Comparison of performing the MR-RATE MRI metadata step (step 7) with and without
this skill. The automated grader EXECUTES the skill for real: it runs the
wrapper against synthetic, PHI-free fixtures and asserts on the real artifacts
and telemetry it produces.

## Without the skill

- The operator must locate the correct upstream script
  (`src/mr_rate_preprocessing/mri_preprocessing/prepare_metadata.py`), assemble
  the many `--processed-dir / --modalities-json / --input-csv /
  --patient-mapping-csv / --study-date-mapping / --output-csv / --repo-id /
  --batch-id / --skip-upload` arguments by hand, and set `PYTHONPATH` to the
  MR-RATE `src` tree.
- No environment-alignment check: a missing dependency or a wrong repo root
  surfaces only as a mid-run traceback.
- No structured record of what ran, on which host, with which package versions,
  or how long each phase took.
- Easy to accidentally point at the read-only source tree or produce output in
  an unexpected location.

## With the skill

- One wrapper, `scripts/run_metadata_prepare.py`, builds the exact upstream
  argument list and injects the correct `PYTHONPATH`.
- A fail-fast **preflight** verifies execution-environment alignment first — the
  exact upstream script exists and the required deps (`pandas`, `openpyxl`,
  `numpy`, `nibabel`) import — and is also exposed standalone via `--preflight`
  so dev/test/prod can gate a run before executing anything.
- The genuine upstream metadata step runs via subprocess (never a stub) against
  synthetic fixtures generated by `fixtures/generate_fixtures.py --step
  metadata`.
- Structured **telemetry** is emitted as one JSON object on stdout and written
  to `out/telemetry.json`: per-phase timings (`preflight_s`, `upstream_s`),
  environment facts (Python/package versions, host, platform, timestamp,
  resolved upstream script path), I/O counts, and the exact command.
- The cleaned per-batch metadata CSV is written to `out/metadata.csv`.

## What the executed check guarantees

- The real-environment preflight passes (aligned == true) on a correctly
  configured host.
- The real upstream metadata step runs to completion on synthetic fixtures and
  produces the expected artifact (`out/metadata.csv`), with sensitive
  UID/accession columns dropped and patient IDs / anonymized study dates merged.
- The emitted JSON conforms to `validators/output_schema.json` and includes a
  populated `telemetry` block; assertions are made against these real artifacts
  and telemetry values, not mocked responses.

## Known gaps

- Upstream `accession_to_uid` anonymization is an identity pass-through, so
  study-ID de-identification is a no-op unless inputs are pre-anonymized.
- Fixtures are small and synthetic; they exercise the code path but are not
  clinically representative.
- This is not a regulatory de-identifier and is not for clinical use.
